# Bounded RAG pipeline

Status: RAG-1 candidate, pending independent review. Synthetic checks do not establish real HCMIU coverage or grounding quality. OpenAI model availability, live credentials and prices remain unverified; no paid application calls are authorized by this change.

`AI_MODE=disabled` and `AI_LIVE_CALLS_ENABLED=false` remain defaults. `EVIDENCE_PROVIDER=openai` is the initial mode. OpenAI is always used for embeddings, reranking and generation. Explicit `jev` selects Jev for evidence sufficiency/conflict and claim support; it requires the Jev key/model and both Jev rates and never falls back to OpenAI. Default OpenAI needs only its key, explicit chat model and three dated rates. Capabilities, ask admission and indexing share this policy, including selected-provider failure cooldowns. No price or chat-model default is supplied.

The question is embedded with the existing 1536-dimensional embedding model. Lexical and semantic retrieval each read at most 24 authorized passages, using RRF to retain at most eleven seeds plus one approved one-hop graph passage. Every passage retains institution, active membership, visibility, current approved version, indexing and effective-date filters. Graph additions require approved evidence-backed edges and an authorized seed; graph metadata is never independent factual evidence.

One OpenAI Responses call orders a subset of the at-most-twelve candidates using excerpts capped at 700 Unicode scalars. Excerpt packing caps the serialized question/evidence envelope at 20,000 bytes. The validator accepts only unique IDs actually transmitted, even when packing drops a candidate. At most four full passages in returned order are packed into the same 20,000-byte context budget. The independent evidence gate sees these full passages, not just excerpts. It must return sufficient evidence with no conflict; insufficient, uncertain or conflicting evidence abstains.

Generation returns at most ten atomic claims, each with unique authorized evidence IDs. A separate support gate checks every claim against only its cited passages, including dates, numbers, negation and conditions. Missing/duplicate claim indices, foreign evidence IDs, missing required fields or malformed verdicts fail closed. Unsupported, uncertain or conflicting claims cause abstention. OpenAI uses typed verdicts, not generated probabilities. Jev retains exact question-ID and finite probability validation. Separate checks by the same provider can share mistakes and are not a factual guarantee.

OpenAI support entries may arrive out of order, but each `claim_index` must identify exactly one generated claim. A supported entry must confirm exactly that claim's citation set; a strict subset fails closed and retains its dispatched reservation. Only an overall `supported` verdict can publish claims. Final citation authorization and persistence remain in the existing transaction.

All OpenAI auxiliary calls reuse the explicit `OPENAI_CHAT_MODEL`, strict Responses JSON schemas, `store:false`, no tools and a 4,096-token output bound. Shared validation checks exact configured model identity, completion/refusal/tool output, a single structured text result, bounded usage and consistent totals/details. No compatible aliases are guessed. Every request is bounded before reservation. No provider request retries automatically.

The shared strict JSON parser rejects duplicate object keys recursively in Responses envelopes and structured text, raw Jev responses and raw embedding responses before constructing normalized JSON values or typed maps. Keys are compared after JSON escape decoding, so escaped-equivalent spellings also reject, including repeated Jev answer IDs and embedding vector/usage fields. Ambiguous fields are never chosen, merged or corrected. Valid nested arrays/objects, numbers and Unicode retain normal JSON semantics; exact citation-set, model, expected-ID, finite-score, usage and vector checks remain enforced. Rejected dispatched responses retain their reservations and cannot authorize another paid dispatch on replay. Structural validation does not establish semantic quality.

Each stage identity hashes the provider, RAG prompt/schema version and exact request, including model. Root ask identity additionally binds the body to the configured execution contract, including exact generation/embedding requests and evidence-provider/prompt/schema versions, excluding secrets. Both completed and racing replay reject incompatible contracts without another provider call; historical answer reads are separate.

Each token operation reserves the existing conservative input/output maximum and settles only validated results. Invalid or ambiguous dispatched stages retain reservations. Same-month never-dispatched recovery reuses the original receipt only with an identical cost plan. Under ownership and global accounting locks, a proven never-dispatched prior-month receipt may be safely released and replaced with a current-month receipt at current dated prices; already safely released stages may also recover. All receipts are retained, the three-attempt bound and monthly/carry caps remain, and failed replacement rolls back the release. Dispatched/uncertain/settled-without-result stage/root receipts stay fenced. Settlement and reservation acquire ownership locks before the accounting lock. No dispatched paid request is automatically retried.

Embedding has a 30-second deadline, each reranking/selection/support call 15 seconds, and generation 45 seconds. The existing overall 140-second work timeout and 150-second HTTP limit remain. A disconnected client does not cancel the bounded server task. Timeouts preserve dispatched funds.

Successful answer/abstention trace storage contains stage durations, provider/model/version, counts, selected evidence IDs and stage/reservation references with reserved and settled micro-USD amounts. It contains no prompts, document quotes, personal question text, secrets or model reasoning. Failed operations retain financial stage receipts; this change does not add durable failed-stage timing storage. Membership/source/graph mutation locks remain held through answer/citation commit. Persistence uses a five-second lock timeout and eight-second statement timeout. After blocking writes, final session introspection uses no second DB connection, then current cited/graph-seed eligibility and ownership/expiry are rechecked on the held transaction immediately before commit. Any failure rolls back publication. Identity is a separate service; revocation after the last observation cannot be made atomic with PostgreSQL commit.

Software fixtures use loopback HTTP and a disposable runtime-role PostgreSQL database. They exercise bounds and contracts, not semantic judgment quality. Real evaluation still needs approved HCMIU source versions, held-out English/Vietnamese questions and human evidence labels. Report recall, citation support/completeness, abstention, latency and cost separately. See [acceptance](acceptance.md); the evaluation worker owns corpus/harness work.

Contract reference: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses), consulted 6 October 2026. Schema adherence alone does not establish factual support.

Design provenance: concepts from the [NVIDIA RAG Blueprint](https://build.nvidia.com/nvidia/build-a-rag-pipeline) and its [query-to-answer pipeline](https://github.com/NVIDIA-AI-Blueprints/rag/blob/main/docs/query-to-answer-pipeline.md) informed the retrieval, reranking and generation stages. This implementation uses the existing Rust/PostgreSQL stack with OpenAI. It is not an NVIDIA deployment or a feature-equivalent copy; the references make no benchmark or quality claim for this candidate.
