### Focus areas checked with no finding

- **Tenant isolation.** Every query against `web_documents`, `web_searches`, `evidence_scores`, `ontology_jobs` and graph writes is scoped by `institution_id`. `evidence_scores` has a composite FK to `chunks(institution_id,id)`. The DB suite asserts ontology never crosses tenants (`crossed == 0`) and that another user gets 404 on a personal space. Personal spaces are excluded from `GET /institutions`. There is no API path that invites someone into a personal space (invitations are operator-only).
- **Web evidence is never labelled approved.** Web captures are `origin='web'` with `draft` versions, and `origin` is immutable (trigger). Version actions, ingestion and URL fetch filter on `origin='approved'`. `CURRENT` needs `v.status='approved'`, which no web version can reach through the API. Answers that cite web evidence are `qualified`. Promote creates a new approved-origin source in `pending_review`. `POST /search` is approved-only.
- **SSRF.** Every `final_url` goes through `ssrf::web_url` (https, no credentials, port 443 only, a DNS name, no local suffixes) and `public_host`, which requires every resolved address to be public. The server never fetches web URLs itself. Caveat: under `cfg(test)`, `public_host` uses the `TEST_HOSTS` fixture branch, so the real DNS-resolution branch is never exercised by any test (**unverified**).
- **No retries, and the ledger is used.** The TinyFish client has `retry(never)` and the test asserts exactly 2 hits for 2 calls. Jev, batched embeddings and ontology extraction reserve through `Attempt::reserve` with per-stage names (`scores_N`, `web_embedding_N`, `extract_N`, `relations_N`). The Jev model is validated against `JEV_MODELS`. Body caps are 60 000 bytes against reservations of 64 000 tokens.
- **Confidence maths.** `overall = answers·√relevance·school·trust` with `trust = 1` on a matching domain and `0.5 + 0.5·source` otherwise. A passage is dropped when `injection > 0.5` or `overall < min`. Claim confidence is the minimum cited overall times the Jev support probability. Answer confidence is the minimum over claims. All three match the order, with unit tests.
- **Domain matching.** The evil-suffix, `xhcmiu`, IDNA/punycode and IP-literal cases are all correct (unit test).
- **402 handling.** The DB suite asserts a 402 produces an abstention with an explanation, not a 500.
