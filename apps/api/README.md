# Rust evidence pipeline receipt

Status: implemented and tested with synthetic PostgreSQL data and injected HTTP providers; pending integration and independent audit. No live AI, real identity, email, approved university corpus, deployment, push or merge was used. Root README release claims remain coordinator-owned.

## Executable behavior

- Configuration loads both provider keys and the selected OpenAI generation model. Live execution requires the existing explicit flags and valid reviewed prices. Missing configuration/prices fail closed. No price rows ship in migrations. Production provider hosts are fixed; test transport injection is compiled only into unit tests, which reject non-loopback provider requests.
- PDF/text uploads and official URL fetches create immutable checksummed versions with optional `en`/`vi` metadata, defaulting to `en`. Text preserves Unicode scalar offsets and line endings. Chunks are at most 2,000 characters / 8,000 bytes, with at most 512 chunks. Duplicate checksums are rejected before another original is written. PDF/HTML extraction uses resource-limited child processes; scans/parse failures quarantine.
- Fetch uses only the saved HTTPS URL. The frozen `hcmiu` allowlist is exactly `edusoftweb.hcmiu.edu.vn`. Every redirect (maximum three), every DNS address and the connected pinned IP are checked. No proxies or automatic retries. PDF is capped at 20 MiB; text/HTML at 2 MiB. Fetching never approves content or crawls links.
- One native worker indexes one chunk per tick. Row selection and a dedicated PostgreSQL session lock prevent concurrent dispatch. Committed embedding results support recovery after settlement without another HTTP call. Explicit `retry_index` by a current institution administrator resumes disabled/failed uploads within the existing three-failure limit, including after uploader revocation/deletion. The same operation and stage IDs are retained; its root is assigned to the recovery actor, with a fresh private idempotency key and a 24-hour window. `response.recovery_actor` and `response.recovered_at` record recovery without changing the Job wire shape. Dispatched/uncertain stages remain fenced.
- Approval changes only the selected version and the current-version pointer. It does not archive siblings. Archiving a historical version cannot clear another current version. Ordinary answer retrieval requires current, approved, ready, effective and visible sources. Student historical version, chunk, original, source and citation reads require a non-null prior approval timestamp as well as current membership/visibility. Archiving a never-approved draft does not publish it.
- Answers embed the question, retrieve lexical/vector candidates (24 each), fuse ranks with RRF and retain three passages plus at most one approved one-hop graph expansion. Jev selects relevant evidence and detects conflicts. OpenAI Responses returns strict claims/UUIDs with no tools. A second Jev call checks each claim's actual text against only its cited passages, including numbers, conditions and contradictions. Unknown, unsupported or conflicting results abstain; Jev failure never bypasses checks.
- Answers and citations commit atomically. Identity is re-introspected after inference; membership and current source validity are locked before persistence. Completed idempotent replay reloads the persisted answer with current access checks. Conversations are owner-scoped, including for administrators. Follow-ups can be stored in the selected conversation; previous conversational text is not automatically reinjected into retrieval.
- Graph entity creation, candidate edges, approval/rejection and listing are wired. Institution FKs and approval-time evidence checks enforce provenance. Listing cursors are signed and bound to institution, requester and role.
- Capabilities consume the exact identity `/internal/capabilities` response through fixed loopback Host/bearer, without redirects/proxies/retries. The same full provider/five-price gate runs before new asks and indexing work; per-stage expiry checks remain. Observed transport, HTTP and malformed-output failures mark the affected provider unavailable in process-local state. New work is blocked for 30 seconds. Capabilities remain `provider_failed` until an explicit operation after cooldown obtains valid output from that provider; no paid health probe runs. Restart clears this process-local observation, not unresolved financial reservations. Availability means ready to attempt, not externally verified.
- Internal account cleanup removes conversations, feedback and memberships, revokes associated invitations and clears personal stage caches. Late provider replies settle money without restoring deleted text. Cleanup is idempotent. Identity deletion remains a separate transaction: if it fails after product cleanup, product access stays revoked and retry is safe. A bounded worker pass actually deletes up to 100 expired conversations.

## Money and interruption

`0004_pipeline.sql` adds durable child stage IDs under the root request, unique stage/input hashes, recoverable results, immutable version language and operational indexes. Existing migrations are unchanged. Each paid stage reserves the complete component plan and commits, then exclusively marks dispatch and commits before HTTP. Separate stage IDs avoid misusing `(root_operation, attempt<=3)` as a three-stage ceiling.

The existing global USD 50 UTC monthly ceiling and prior-month carry remain enforced in PostgreSQL. Zero-rate components remain in reservation and settlement plans. Cached OpenAI input is charged conservatively at the ordinary input rate. No tools are enabled, so generation cannot incur hidden search/tool charges.

No HTTP client retries automatically. Deadlines: embeddings 30 seconds, Jev 15 seconds, generation 45 seconds, complete answer 140 seconds, outer answer HTTP 150 seconds. Two pipeline slots bound concurrent answers. Requests are capped at 64 KiB and provider responses at 512 KiB. A disconnected caller does not cancel the bounded answer task. The existing 14-second shutdown drain may interrupt it: dispatched funds remain reserved and stale pending roots become failed on recovery. Failed/ambiguous idempotency keys return conflict instead of dispatching again.

Never release dispatched/uncertain charges because of timeout, cancellation, parse failure or cleanup. Reconciliation requires authoritative provider evidence. Recovery requires the retained original operation root; missing roots fail closed with conflict. Root retention is owned by the identity/ops repair lane. Recoverable institution-owned chunk vectors survive uploader deletion and cache expiry, including validated vectors settled after uploader deletion; personal answer caches remain scrubbed. Completed or unrecoverable job caches are still eligible for expiry cleanup. If an old settled cache was already scrubbed before this repair and before its embedding was saved, recovery cannot redispatch that stage; operator reconciliation is required. No schema change or grant expansion is used.

Ask, search and embedding inputs share the 4,000 Unicode scalar / 16,000 UTF-8 byte boundary. Tab, LF and CR are allowed; other ASCII controls are rejected. Question-only evidence envelopes are validated before admission; evidence trimming is a pure terminating operation. Full Jev request size is checked before reservation. Embeddings reserve 16,000 token units, conservatively bounded by accepted UTF-8 bytes, rather than assuming scalars equal tokens; provider-specific token limits may still reject a request. Generation and Jev conservative bounds are unchanged.

## Review interfaces and original reconciliation

`GET /api/v1/institutions/{institution_id}/versions/{version_id}/chunks` returns ChunkPage for current administrators, including pending/quarantined/archived versions. Its signed ordinal/ID cursor binds institution, version, admin role, requester and ordering. An empty extraction produces an empty page. `GET /api/v1/institutions/{institution_id}/feedback/{feedback_id}/context` returns exactly the existing report, question and answer, without identity fields or adjacent conversation turns. The current administrator and report are checked and locked; evidence retains the answer owner's current authorization restrictions. Hidden evidence fails closed. An answer ID alone confers no review access. Responses are no-store.

All newly ingested PDF, HTML and text chunks use half-open Unicode scalar offsets relative to that normalized chunk: `[0, chunk.chars().count())`. Existing migration files and immutable old chunk rows are untouched. There is no approved production data. Old synthetic test sources must be recreated from originals under fresh source IDs (same-source checksum deduplication prevents blind reupload), or rebuilt through a separately authorized disposable database workflow. A future non-disposable data upgrade needs a coordinator-owned migration/reindex plan; this repair does not silently rewrite immutable provenance.

Plain-text chunk limits are checked before original creation. A request-owned cleanup guard removes its original after known precommit errors, parser-capacity rejection and task cancellation; parser sidecars also have cancellation cleanup. Malformed/scanned documents that successfully commit a quarantined version deliberately retain their originals. Immediately before dispatching COMMIT, cleanup is disarmed: a lost commit acknowledgment must never delete a potentially committed original. Process crashes, unlink failures and ambiguous commits can therefore leave private files. No automated orphan sweeper or financial reconciliation is claimed.

Operator reconciliation is a separate, approved, bounded maintenance procedure: pause ingestion, inspect at most 100 UUID originals older than 24 hours per pass, and compare each full storage key against `product.source_versions` in the authoritative database. Keep every referenced file; stop if database/commit state cannot be established. Record candidate keys in a private operator artifact and require a separate deletion decision after rechecking references. Do not infer orphanhood from directory age, a missing job, a timeout, or a replica. Repeat bounded passes only after reviewing outcomes. This procedure is documented, not implemented or exercised as a production cleanup command.

SSRF denies the complete `3fff::/20` documentation allocation, including `3fff::1`, as specified by the [IANA IPv6 special-purpose registry](https://www.iana.org/assignments/iana-ipv6-special-registry) and RFC 9637.

## Remaining boundaries

- Optional official-host OpenAI web discovery is **not implemented**. Discovery stays disabled and `discover:true` fails before paid calls. No search result enters approved evidence implicitly.
- Live credentials/model availability, real HCMIU retrieval and grounding, held-out bilingual evaluation, SMTP, Google, integrated NOTI-6 account deletion and independent audits remain unverified. Mock probabilities do not prove semantic accuracy.
- SSRF tests cover URL/IP/redirect denial and rejection of an actual connected loopback socket. Controlled public-TLS/DNS-rebinding integration was not run. Adversarial parser corpus/load tests, 500-page boundaries, backup/restore and release builds remain release work.
- Shared TS schemas and endpoint manifest extensions belong to NOTI-6. Language is persisted in SQL/chunks while the existing Version output remains unchanged. The new version-language column and indexes in 0004 require integration-owner review alongside the stage table.
